# 练习阶段索引

> 格式借自 CodeCrafters：**每个阶段 = 一个可验证的行为 + 一份规格 + 一组必须全过的验收**。
> 不讲"这一章介绍什么"，只讲"做完这一阶段，什么现象必须成立"。

---

## 为什么这种格式适合练习

| 机制 | 作用 |
|---|---|
| 阶段小到一次能做完 | 每阶段 1~3 小时，随时能停，不会烂尾 |
| 验收是**命令**不是"理解" | 跑不通就是没做完，没有自我欺骗的空间 |
| 规格写死边界 | 边界值、错误码、并发要求都写清楚，避免"我觉得应该这样" |
| 阶段有前置依赖 | 前一阶段的产物是后一阶段的输入，跳步会立刻暴露 |
| 完成后能立刻看到现象 | 每阶段末尾都有一条能跑的命令，反馈周期短 |

**唯一的不同**：CodeCrafters 有平台帮你跑测试，这里没有。所以每个阶段的验收都写成你能直接复制的 `curl` 或断言，**跑不通就不算完**。

---

## 阶段划分

依赖是线性的，但 05 之后可以按兴趣跳（06 与 07 可互换）。

**版本与阶段不是一回事**：01~09 合起来是 v0（卖课闭环），10~11 是 v0.1（评论），12 是跨版本的对账能力。
详见 `../../README.md`。

| # | 阶段 | 目标一句话 | 主验证的不变量 |
|---|---|---|---|
| 00 | 骨架 | 服务能起，一个接口能通，日志能按 requestId 串起来 | — |
| 01 | 账号与身份 | 手机验证码登录能拿到会话 | 一账号多身份 |
| 02 | 课程与班期 | 能查到课程详情和可售班期 | — |
| 03 | 券试算 | 传入班期能算出"哪些券可用 + 最优券" | 试算纯读，可重复调用 |
| 04 | 名额冻结 | 扣名额要么全成要么全不成 | 名额守恒 |
| 05 | 下单 | 重复提交只出一张单 | 下单幂等 |
| 06 | 支付回调 | 重复回调只生效一次 | 支付幂等 |
| 07 | 授权 | 支付成功后能访问课程，进度可上报 | 一单一授权、进度不可逆 |
| 08 | 超时关单 | 15 分钟未付自动关单并释放 | 名额守恒 + 迟到支付异常通道 |
| 09 | 退款 | 双闸门判定 + 失败可回退 | 金额自洽 |
| 10 | 评论发布 | 提交即可见（仅自己），审核后公开 | 可见性与审核解耦 |
| 11 | 编辑重审 | 改内容必须重新审 | 版本一致 |
| 12 | 对账 | 所有不变量变成能定时跑的检查 | 全部 |

## 每个阶段文档的固定结构

```markdown
# Stage NN · 名字

## 目标        一句话，必须可观察
## 规格        接口、请求响应、规则、边界
## 验收        可复制的命令，必须全过
## 禁止        本阶段不许引入的东西（防止提前上组件）
## 提示        先别看，卡住再看
## 常见错误    别人踩过的，通常也是你会踩的
## 完成后      下一阶段，以及本阶段留下的已知缺口
```
