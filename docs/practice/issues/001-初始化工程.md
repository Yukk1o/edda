# [infra] 初始化工程与依赖基线

> M0 骨架 · 无依赖 · 预计 1~2 小时

## 背景

没有骨架，后面每个 issue 都在挪地基。这个 issue 的唯一目的：让项目能编译、能启动、依赖清单干净。
**依赖清单比代码重要** —— 一个提前引入的 Redis，会让后面五个 issue 都绕着它写。

## 范围

- 单模块 Maven 工程，Boot 4.1.1 + JDK 25（与本地环境一致）
- 依赖只允许：`web`、`jdbc`、`validation`、`actuator`、`mysql`、`lombok`、`test`
- 包结构按领域划分：`auth` / `course` / `coupon` / `stock` / `order` / `payment` / `enroll` / `comment`，外加 `common`
- 每个领域包放一个 `package-info.java`，写明职责与"允许依赖谁"
- **依赖方向门禁**：引入 ArchUnit（test scope），用规则禁掉反向依赖，`mvn verify` 失败即拦住
- `.gitignore`（target、IDE、日志）

## 不做

- 不引入 Redis / MQ / Spring Cloud / 网关 / ES / Seata（见 `../../decisions/0006-组件准入.md`）
- 不写任何业务代码，不建任何表（库连通性属于 005）
- 不做多模块拆分（一个进程就是多模块的反面）

## 验收

- [ ] `mvn -q -DskipTests package` 返回 0
- [ ] 启动后 `/actuator/health` 返回 `UP`
- [ ] 依赖清单负向检查，四条都必须为空：

```bash
mvn dependency:tree | grep -Ei "redis|kafka|amqp|spring-cloud|elasticsearch|seata" || echo "clean"
```

- [ ] 每个领域包都有 `package-info.java`，且写明允许依赖方向
- [ ] ArchUnit 规则生效：故意让 `coupon` 依赖 `order`，`mvn verify` 必须失败；改回来后通过

## 依赖

无

## 备注

**JDK 23+ 的坑**：javac 不再隐式扫描 classpath 上的注解处理器，Lombok 会静默失效，
报错还会伪装成「无法推断类型参数」。必须在 `maven-compiler-plugin` 里显式声明
`annotationProcessorPaths`，否则你会花两个小时查一个不存在的泛型问题。

包结构不要按 `controller/service/mapper` 这种技术分层做顶层，那会让领域边界从第一天就模糊。
按领域切，技术分层放在领域内部。
