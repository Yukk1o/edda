# ADR 索引

> ADR 记录**已经发生或正在发生的决定**，不写"以后可能怎么决定"。
> 提前写的 ADR 只是猜测，而且会变成"我们当初说好了"的伪约束。

## 什么时候必须写

命中任意一条就写：

1. **要引入一个有状态的组件**（缓存、消息队列、搜索引擎、注册中心、调度中心）
2. **决策会导致数据迁移或接口不兼容**（改模型、改契约、改状态机）
3. **存在两个以上合理方案，且必须选一个**（拆分方式、通信协议、一致性与可用性的取舍）
4. **已经踩过一次坑并因此改变了做法**（这类最有价值，因为它有代价做背书）

## 什么时候不写

- 实现细节（怎么命名、用哪个工具类、代码放哪个包）
- 可以随时改且不影响数据的决定
- 还没碰到的问题——**写下"待触发"，而不是写下"结论"**

## 状态定义

| 状态 | 含义 |
|---|---|
| 提案 | 已写但未定，等实际动手时验证 |
| 已采纳 | 当前生效，代码按它写 |
| 草案 | 结论先放着，触发条件到了再定稿（**不要按草案写代码**） |
| 已废弃 | 被新 ADR 取代，保留原文并在顶部标注取代者 |

编号只增不改，不复用。废弃的 ADR 不删除——它是"我们曾经这么想"的记录。

## 已明确的边界（不需要 ADR，属于常识约束）

- OAuth 登录只取外部用户 id 写入 `user_identity.identifier`，access_token 与 refresh_token 用完即丢
- `identifier` 必须是稳定不可变的外部 id，不用 username、昵称这类可改字段
- 只有在需要"代表用户调第三方接口"时才引入 token 存储，且必须加密列存储
