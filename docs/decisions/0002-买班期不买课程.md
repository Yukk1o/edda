# 0002 用户买班期，不买课程

- 状态：已采纳
- 日期：2026-11-26
- 影响：course / order / coupon

## 背景

课程是内容实体（大纲、讲师、简介），它的价格和售卖时间会随期次变化。
如果直接对课程定价，改价会污染历史订单，也无法支持"同一门课开两期、不同价格"。

## 决策

`课程 1:N 班期`，**班期是唯一的售卖单元**。价格、名额、售卖起止时间、开课时间全部挂在班期上。
订单只引用班期，不引用课程；授权最终落在课程上（用户买班期，获得的是课程访问权）。

订单明细保存价格快照，商品改价不影响历史订单。

## 代价

- 用户需要理解"班期"这个概念，前端要有明确的期次选择
- 同一课程多班期时，课程简介需要重复维护
- 增加一层关联，查询"我买过这门课吗"需要跨班期聚合

## 替代方案

| 方案 | 否决理由 |
|---|---|
| 直接卖课程 | 无法支持多期、多价格；改价会改动历史订单金额 |
| 课程上挂多个价格（价格表） | 本质上就是班期，只是换了个名字，还会让库存与售卖期无处安放 |

## 备注

"长期售卖、名额不限"的课程是班期的一个特例（无结束时间、名额设为一个足够大的值），
不需要新增模型。
