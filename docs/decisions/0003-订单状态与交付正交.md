# 0003 订单状态只管钱，交付状态独立

- 状态：已采纳
- 日期：2026-11-26
- 影响：order / enroll

## 背景

支付成功和授权成功是两件事。授权可能失败：课程被下架、授权服务异常、用户已有有效授权。
如果用一个状态机同时表达"钱到了"和"能看了"，会不断长出新状态
（`PAID_DELIVERED`、`PAID_DELIVERY_FAILED`），退款时还要判断"退一个已交付的"。

## 决策

订单状态机只表达**资金归属**，五个状态：`CREATED` / `PAID` / `CLOSED` / `REFUNDING` / `REFUNDED`。

交付是独立的维度：一条"待交付任务"，状态为 `PENDING` / `SUCCESS` / `FAILED`，失败可重试。
"已付款但未授权"是一个**正常可见的中间态**，不是异常。

补充两条：

- 部分退款不新增状态，用「已退金额」表达；退满才迁移到 `REFUNDED`
- 关单后收到支付回调属于外生异常，不改订单状态，落「异常收款」并自动发起退款

## 代价

- 需要多一个交付任务的视图与监控指标
- "已付未授权"必须有告警，否则会静默堆积
- 前端要能表达"已购买、授权处理中"

## 替代方案

| 方案 | 否决理由 |
|---|---|
| 合并成一个状态机 | 状态爆炸，退款分支无法收敛 |
| 支付回调里同步建授权，失败就回滚支付 | 支付渠道的回调不能回滚，钱已经到账了 |

## 备注

退款失败必须能回到 `PAID`（渠道会超时、会拒绝）。没有这条回路，订单会永久卡在 `REFUNDING`。
